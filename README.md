# מערכת IVR - הקראת תנ"ך ותלמוד עבור ימות המשיח

## מה זה

מערכת שלמה (שרת Node.js + pipeline להפקת תוכן) המיישמת את המפרט שביקשת:
תפריט נושא → ספר → דף → עמוד, הקראת עמוד גמרא עם פקדי ניווט מלאים
(5 שניות / 3 דקות אחורה-קדימה, שינוי קצב, עצירה), תפריט מפרשים
(רש"י/תוספות) עם זיכרון מיקום אישי לכל מפרש בנפרד, ותפריט מידע
(מסכת/דף/עמוד/דקה + מעבר בין דפים).

**עדכון חשוב לעומת התכנון הראשוני:** בדיקה מול התיעוד הרשמי של ימות
המשיח העלתה שרוב פקדי הניווט (1/3/4/6/7/9/5) הם **פיצ'ר מובנה** של
ימות (`control_playX`), ולא דורשים שרת בכלל. רק שני דברים דורשים
שרת חיצוני: מעבר בין מפרשים עם זיכרון מיקום, ותפריט המידע/ניווט-בין-דפים.
המערכת כאן בנויה סביב זה - מינימום תלות בשרת, מקסימום שימוש בפיצ'רים
נייטיביים של ימות (יציב יותר, מהיר יותר, פחות תחזוקה).

## מבנה הפרויקט

```
server/
  index.js          - שרת ה-API הראשי: תפריט נושא/ספר/דף/עמוד
  playerApi.js       - טיפול במקש 2 (מפרשים) ומקש 8 (מידע/ניווט)
  yemotProtocol.js    - בונה תגובות בפרוטוקול המדויק של "מודול API"
  audioEngine.js      - חיתוך/מהירות אודיו (ffmpeg) - שימושי להרחבות עתידיות
  db.js               - SQLite: זיכרון מיקום אחרון לכל (טלפון,עמוד,מפרש)
  contentIndex.js     - קריאת קבצי המטא-דאטה שה-pipeline מייצר

pipeline/
  scrapeWikitext.js   - שליפת טקסט מוויקיטקסט + זיהוי טקסט מודגש
  ttsProvider.js      - ממשק להחלפה מול כל ספק TTS (Azure/Google/...)
  buildAudio.js       - TTS לכל קטע + חיבור ffmpeg + מפת זמנים (timeline.json)
  uploadToYemot.js    - העלאת הקבצים לשלוחות בימות (**דורש אימות - ראה למטה**)
  buildTopicsIndex.js - בונה את תפריט הנושאים/ספרים הראשי
  run.js              - מנצח את כל השרשרת לעמוד בודד

config/
  ext-api-main.ini              - הגדרות לשלוחה הראשית (type=api)
  ext-playfile-daf-template.ini - תבנית ל-ext.ini שנוצר לכל עמוד בנפרד
```

## התקנה

```bash
npm install
cp .env.example .env
# ערכו את .env: TTS_API_URL/KEY, YEMOT_USERNAME/PASSWORD, CONTENT_ROOT וכו'
```

## הרצה

**1. בניית תפריט הנושאים:**
```bash
node pipeline/buildTopicsIndex.js
```

**2. עיבוד עמוד גמרא בודד (בדיקה על מדגם קטן, כדי לוודא איכות לפני הרצה גדולה):**
```bash
node pipeline/run.js "בבא קמא" 2 a
```

**2ב. הרצה אוטומטית על מסכת שלמה או על כל הש"ס** (זו הדרך המומלצת -
אין צורך לקרוא ל-run.js ידנית לכל דף):
```bash
node pipeline/batchRun.js "בבא קמא"        # מסכת שלמה
node pipeline/batchRun.js "בבא קמא" 2 20   # טווח דפים נבחר
node pipeline/batchRun.js all              # כל הש"ס - ריצה ארוכה, השאירו לרוץ ברקע
```
ההרצה **אידמפוטנטית** - ניתן להריץ שוב אחרי עצירה/קריסה, ועמודים שכבר
נבנו (יש להם `meta.json`) ידולגו אוטומטית. כשלונות (לדוגמה תקלת רשת
זמנית) מנוסים שוב עם backoff, ובסוף נשמר קובץ לוג ב-`data/logs/` עם
פירוט מה הצליח ומה נכשל - כדי שתוכלו להריץ שוב ולתקן רק את מה שנכשל.
טבלת מספרי הדפים לכל מסכת נמצאת ב-`pipeline/masechtotDapim.js` - כדאי
לבדוק/להשלים אותה לפני הרצה על מסכת שעדיין לא מופיעה שם.

**3. הרצת השרת:**
```bash
npm start
```

**4. בימות המשיח (בממשק הניהול):**
- שלוחה ראשית: להעלות את `config/ext-api-main.ini`, לעדכן את `api_link`
  לכתובת השרת שלכם (חייב HTTPS ציבורי - Cloudflare Tunnel / VPS / ngrok לבדיקות)
- לכל עמוד: ה-`ext.ini` נוצר אוטומטית ע"י `pipeline/run.js`

## ממשק ניהול (חדש)

לא צריך להריץ הכל דרך שורת פקודה - יש ממשק ניהול מלא בדפדפן, בכתובת
`https://YOUR-SERVER-DOMAIN/admin` (אותו שרת בדיוק, לא שירות נפרד).

**מה יש בו:**
- **כניסה עם קוד** (`ADMIN_ACCESS_CODE` ב-.env) - לא ניהול משתמשים מלא,
  פשוט קוד סודי אחד לגישה, מתאים לשימוש פנימי.
- **דשבורד** - כל המסכתות עם פס התקדמות (כמה עמודים כבר נבנו מתוך הסך הכל).
- **רשימת דפים במסכת** - לחיצה על מסכת מציגה את כל הדפים שלה עם צבע לפי
  סטטוס (אפור=לא התחיל, זהב=יש טיוטה, ירוק=נבנה).
- **עורך עמוד** - מציג את העמוד בפריסה שמזכירה עמוד ש"ס אמיתי: רש"י מצד
  אחד, גמרא במרכז, תוספות מצד שני. הטקסט נמשך אוטומטית מוויקיטקסט.
  לכל עמודה יש:
  - **↻ משוך מחדש** - שולף מחדש מוויקיטקסט (למקרה שערכת ורוצה לחזור למקור)
  - **🔤 הוסף ניקוד** - שולח את הטקסט לשירות הניקוד האוטומטי של דיקטה
    ומחזיר אותו מנוקד, לעריכה/אישור לפני TTS
  - עריכה חופשית ישירות בתיבת הטקסט (תיקון שגיאות שליפה, ניסוח וכו')
  - סימון קטע כ"מודגש" (יושמע בקול/צליל שונה) ע"י עטיפתו בשלוש גרשיים,
    בדיוק כמו בתחביר ויקיטקסט: `'''כך'''`
- **💾 שמור טיוטה** - שומר את הטקסט הערוך (לפני TTS) כדי שתוכל לחזור אליו
- **🔊 שלח ל-TTS ובנה אודיו** - מריץ את כל שרשרת ההפקה על התוכן הערוך,
  ומציג נגן אודיו לכל track כדי להאזין לתוצאה ישר בדפדפן
- **☁️ העלה לימות** - מעלה את הקבצים הסופיים לשלוחה המתאימה

**הפעלה:** לא צריך שום דבר נוסף - זה חלק מאותו `npm start`. פשוט
גולשים ל-`/admin` בדפדפן אחרי שהשרת רץ.

## מה נותר לוודא/להשלים לפני production (בכנות מלאה)

1. **`pipeline/uploadToYemot.js`** - מבנה קריאת ה-API (login/token/upload)
   מבוסס על ההיגיון הכללי של "API - גישת מפתחים למערכות" של ימות, אבל
   **לא אימתתי את שמות הפרמטרים/הנתיבים המדויקים** (לא הצלחתי לפתוח את
   הדף המלא). יש לבדוק מול https://f2.freeivr.co.il/topic/55 לפני הרצה
   על תוכן אמיתי, ולהתאים את `login()` ו-`uploadFile()` בהתאם.

2. **דפוס השליפה מוויקיטקסט** (`scrapeWikitext.js`) - `buildPageTitle`
   מניח מבנה "בבלי/מסכת/דף עמוד", ופיצול רש"י/תוספות מאותו דף עדיין
   TODO - יש לבדוק בפועל על כמה עמודים באתר לפני הרצה על מסכת שלמה,
   כי המבנה עשוי להשתנות בין מסכתות. **ממשק הניהול עוזר כאן בפועל** -
   אם השליפה האוטומטית של רש"י/תוספות נכשלת, זה יופיע כשגיאה ברורה
   בעמודה המתאימה, ותוכל להדביק את הטקסט ידנית ולהמשיך.

3. **שירות הניקוד** (`pipeline/nikud.js`) - מבוסס על endpoint עובד
   שנמצא בפורום מפתחים (לא תיעוד רשמי מלא), עם `genre='rabbinic'`
   שהוא ניחוש סביר לטקסט תלמודי - לא ערך מתועד רשמית. יש לבדוק את
   איכות התוצאה בפועל בממשק הניהול, ולשקול לנסות גם `genre='premodern'`
   אם התוצאה לא מספקת.

3. **ספק ה-TTS** - `ttsProvider.js` הוא ממשק גנרי; יש לחבר בפועל
   לספק שתבחרו ולוודא תמיכה טובה בעברית/ארמית (זו הבעיה האיכותית
   המשמעותית ביותר בפרויקט - ראה `PHONETIC_FIXES` להרחבה הדרגתית).

4. **פורמט האודיו** - הקוד מניח WAV mono 8kHz PCM (נפוץ ב-IVR טלפוני);
   כדאי לוודא מול "הגדרות מתקדמות - ימות המשיח" העדכניות שזה עדיין
   הפורמט הנדרש.
